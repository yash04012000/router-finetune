# PRD 2 — Dataset: synthetic generation, dedup, splits, realism slice

Status: Not started · Depends on: PRD 1 · Blocks: PRDs 3-7

## Summary

5,000+ labelled support messages across the 16 intents, generated by a published script, split
so that paraphrases of the same seed never straddle train and test, and frozen (hashed) before
any approach sees it. Because synthetic data flatters every model, a small hand-written slice is
added as a reality check, and its results are reported separately.

## Goals

- `scripts/generate_dataset.py`: reproducible LLM-driven generation (cached, seeded).
- ~400 examples per intent (~6,400 total) after dedup; at least 5,000 guaranteed.
- Diversity on explicit axes; deliberate oversampling of confusable pairs.
- Exact- and near-duplicate removal, including across splits.
- Group-aware 70/10/20 train/val/test split, frozen and hashed in `data/splits.lock.json`.
- ~150-200 hand-written examples (`source: handwritten`) as a separate realism test slice.
- `data/DATACARD.md`; dataset published in-repo (JSONL) and mirrored to the Hugging Face Hub.

## Non-goals

- Training or evaluating anything.
- Using any real customer data (CONVENTIONS.md: public or synthetic only).

## Design

### 1. Generation

Each generation call is a **seed spec** → a batch of N=8 variants:

```
seed spec = (intent, persona, tone, channel, length_bucket, multi_turn?, confusable_target?)
  persona:  {first-time buyer, long-time subscriber, small-business admin, non-native speaker, ...}
  tone:     {neutral, polite, frustrated, angry, terse}
  channel:  {chat, email, in-app}  -> affects length, greeting, signature
  length:   {short (<12 words), medium, long (multi-sentence with irrelevant detail)}
  multi_turn: 20% of seeds produce 2-4 turns of context before the routed message
  confusable_target: 25% of seeds ask for a message that is genuinely <intent> but uses
                     vocabulary typical of the confusable intent (e.g. a refund request that
                     mentions "sending it back")
```

The prompt includes the intent's description from `intents.yaml` and the descriptions of its
confusable neighbours with an instruction to stay on the correct side of the boundary. Output is
JSON (list of messages), validated against the schema; invalid batches are retried once, then
dropped and logged.

Post-processing noise (applied by code, not the LLM, so it's controllable and seeded): typos on
10% of examples, lowercasing/no punctuation on 10%.

The generator model must be from a **different model family than PRD 4's evaluated large
model**, so the zero-shot model isn't grading its own phrasing. Generation goes through LiteLLM
with a disk cache keyed on (model, prompt, seed), so re-running the script reproduces the dataset
exactly without new API calls; the cache is committed.

### 2. Quality filtering

- Exact dedup on normalized text (lowercase, collapsed whitespace, stripped punctuation).
- Near-dup: MinHash/Jaccard on word 3-grams (threshold ~0.8), or TF-IDF cosine > 0.9 — whichever
  is simpler to get deterministic. Near-dups are removed *before* splitting, keeping one per cluster.
- Label audit: a second, cheap LLM pass labels every example blind; disagreements (expect a few
  percent) go to a review file. Recommendation: hand-review a sample of ~100 disagreements, drop
  the ambiguous ones, and record the drop count in the data card. Do **not** relabel to match the
  auditor — that would leak a model's opinion into the gold labels.

### 3. Splits

- Grouped by `group_id` (the seed spec), stratified by intent: 70/10/20 → ~4,480 / ~640 / ~1,280.
- Test and val files are written once, hashed into `data/splits.lock.json`, and loaded only via
  `router.data.load_split` (PRD 1), which verifies the hash.
- Hand-written slice is `data/realism_test.jsonl`, never used for training or threshold tuning.

### 4. Hand-written realism slice

~10-12 per intent, written by a human without looking at the synthetic data: short, messy,
ambiguous, multi-issue messages the way real customers write. This is the honest check on
"synthetic data flatters models"; PRD 7 reports every approach's accuracy on it beside the main
test score. Recorded in the data card as hand-written by the author.

### 5. Outputs

```
data/train.jsonl, val.jsonl, test.jsonl, realism_test.jsonl
data/splits.lock.json          # sha256 per file + counts per intent
data/DATACARD.md               # generation method, models, counts, known biases, licence
data/gen_cache/                # cached generation responses
scripts/generate_dataset.py, scripts/dedup_and_split.py, scripts/audit_labels.py
src/router/data.py             # load_split (from PRD 1) + dataset stats helpers
```

## Testing plan

- Generation parsing: malformed/partial JSON from the LLM is rejected; fixed seed + cache yields
  byte-identical output (run against a stub client, no network).
- Dedup: known near-duplicate pairs are collapsed; distinct short messages are kept.
- Splits: no `group_id` in more than one split; per-intent proportions within tolerance; no
  normalized-text overlap between train and test.
- Lock: editing one character of `test.jsonl` makes `load_split("test")` raise.

## Acceptance criteria this PRD unblocks

"Dataset: 5,000+ examples across 10-20 intents, published, synthetic stated, generation script
included." Feeds "honest limitations section covering dataset realism".

## Open questions

1. Generator model choice (needs to differ from the PRD 4 model's family). Budget: ~800 calls
   with short outputs — a few dollars at most on any current mid-tier model.
2. Mix in a public dataset (e.g. a Banking77 subset) as an additional external test? Adds
   credibility but its label space doesn't match the taxonomy. Recommend: skip for v1, mention
   in limitations.
3. Multi-turn share of 20% — enough to show the router uses context, small enough not to dominate.
